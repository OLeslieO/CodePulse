# 公开文档访问 503 诊断

检查日期：2026-09-17。结论：本轮阻断来自自动审批服务使用的 Packy 模型路由，不是已经确认的目标文档网站 503。尚未修复远端渠道，联网调研仍未恢复。

## 实测结果

| 检查 | 实际结果 | 可以得出的结论 |
| --- | --- | --- |
| 受限终端 `curl -I -L https://docs.packyapi.ai/` | curl 错误 6：无法解析主机 | 请求未取得 HTTP 响应；不能判断目标网站是否健康 |
| 受限终端检查 chatgpt.com 和 api.openai.com | 同样为 DNS 解析失败 | 当前受限执行环境无可用外网解析；不证明用户整机网络故障 |
| 环境代理变量 | 未看到 HTTP(S)/ALL/NO_PROXY 环境变量 | 不足以排除系统代理、TUN 或其他网络代理 |
| `scutil --proxy`／`scutil --dns` | 空代理字典／No DNS configuration available | 仅反映当前执行环境可见的信息，不能推断应关闭 Clash 或修改 DNS |
| 授权出沙箱的公开文档 HEAD 请求 | 创建命令进程前被自动审批服务拒绝，服务返回 503 | 阻断发生在工具审批环节，文档请求未实际执行 |
| PATH 中的 `codex --version` | npm 包 0.130.0 的 macOS ARM64 可执行文件缺失，ENOENT | 全局 CLI 安装不完整；这是另一项问题，无法解释远端审批路由 503 |
| Desktop 内置 CLI `--version` | codex-cli 0.154.0-alpha.6.2 | Desktop 的内置二进制可执行，不等于联网功能已恢复 |

## 关键错误

```text
Automatic approval review failed: unexpected status 503 Service Unavailable
分组 codex 下模型 gpt-5.6-luna 无可用渠道（distributor），请尝试切换其他分组
url: https://www.packyapi.ai/v1/responses
request id: 01M2Q333KCYY3XBMHM53X1RK2D
cf-ray: a3c646e9797c0c91-ICN
```

这里的 URL 是审批模型调用地址，不是 docs.packyapi.ai。配置中主对话模型为 gpt-6-astra，但本次审批错误明确请求 gpt-5.6-luna；主对话能运行不能证明审批模型的路由也可用。没有证据表明这是 WebSocket 故障，也没有证据表明修复全局 CLI 会修复该问题。

## 针对性处理顺序

1. 在 Packy 控制台或向其支持人员确认：当前凭据所属的 codex 分组是否为 gpt-5.6-luna 提供可用渠道。可以提供上述请求 ID 定位，无需提供密钥。
2. 若支持其他分组，应先由 Packy 确认哪个分组支持该模型及其计费变化，再调整对应路由／凭据所属分组。不要只修改主对话模型，审批模型是另一次调用。
3. 若客户端有官方支持的审批模型配置，可使用当前供应商确实支持的模型；目前没有核实此客户端是否暴露这项设置，不能提供猜测的配置键。本次未修改审批策略或自动审批机制。
4. 渠道恢复后再运行一次只读公开文档请求，确认审批通过并收到文档内容。只有审批通过后仍出错，才继续调查目标网站、代理或 WebSocket。

不建议为这个已定位的路由错误关闭代理、放宽沙箱、关闭审批或重复请求同一 URL。未重启 Desktop，以免中断当前任务；未变更供应商分组、密钥或系统配置。

全局 CLI 的安装损坏可另行通过官方 npm 安装流程修复；当前 Desktop 的内置二进制可完成版本诊断，因此未为本次网页 503 擅自重装 CLI。

## 当前调研的后续

### 尝试查找审批模型切换入口

用户随后授权尝试 Luna 之外的审批模型。已读取 Desktop 内置 CLI 帮助、其生成的 app-server 协议 schema，以及应用中与审批模型有关的静态字段：

- `--model` 只说明选择 agent 模型，没有保证覆盖自动审批模型。
- 当前会话提供的工具调用参数没有审批模型覆盖选项。
- 协议中的 `approvalsReviewer` 表示审批交给用户或自动审查，不是模型选择。
- 二进制存在 `auto_review_model_override` 等内部字段，但未验证它们是可供用户设置的配置键，也未发现对应 Desktop 设置入口；未改写模型目录或程序文件。
- 尝试通过 `--strict-config` 与 `debug models` 进行离线参数验证，被 CLI 以该子命令不支持 strict-config 拒绝。此结果不证明候选配置字段有效或无效。

因此本次没有真正用另一模型运行自动审批，不能报告访问测试成功或失败。用户已授权尝试，阻碍是缺少已验证且能作用于当前会话的切换接口，不是缺少用户同意。未修改主模型、审批策略或供应商路由。

恢复上述渠道后，继续读取 Packy 官方账单文档与 GitHub 仓库，补齐接口、技术栈、架构和许可证证据，然后向用户提交完整 Review。当前方案的相关“待核实”不能提前改成“已支持”。
